# 통합 스펙(suite.json) 스키마

4개 빌더가 공유하는 단일 입력이다. `parse_ordinance.py`가 조례안 파일에서 만들고,
빠진 값은 사람이 채운다.

## 공통

| 키 | 타입 | 필수 | 쓰는 서식 | 설명 |
|---|---|---|---|---|
| `조례명` | str | ● | 4종 전부 | 「」 없이. 파일명에도 쓰인다 |
| `유형` | str | ● | 4종 전부 | `제정`·`일부개정`·`전부개정`. **공용 규칙**(`scripts/ordtype.py` `detect_type`): 제명 공백 제거 후 `전부개정`→전부개정, `일부개정` 포함 또는 `개정조례안`·`개정규칙안`으로 끝남→일부개정, 그 밖→제정. 명시 `유형`이 이기지만, 제명이 개정형인데 명시 유형과 다르면 **충돌로 중단**한다 |
| `공포기관` | str | | 완성본·표준서식·입법예고 | 공포번호행 접두 — `경기도`, `경기도교육청` 등 |
| `대표발의` | str | ● | 완성본·입법예고·서명부 | 성명만(직함 없이) |
| `발의연월일` | str | | 완성본 | `2026년 08월    일` 형태. 미정이면 빈칸형 |
| `발의자` | str | | 완성본 | 표지 표의 발의자 칸 |
| `소관위원회` | str | | 입법예고 | 예고문의 `○○○위원회`. 비면 빌더가 `○○○위원회`를 찍고 경고, run_suite는 WARN |

## 제안설명서

| 키 | 타입 | 쓰는 서식 | 설명 |
|---|---|---|---|
| `제안이유` | str[] | 완성본·입법예고 | 문단 단위. 입법예고 서식은 `가. 나. 다.` 항목 체계이므로 산문이면 항목화 검토 |
| `주요내용` | str[] | 완성본·입법예고 | 각 항목 끝에 `(안 제○조)` 근거 표기 |
| `참고사항` | str[] | 완성본 | 가.관계법령 나.입법예고 다.비용추계서 라.검토의견 마.예고결과. 생략 시 빈칸형 기본값 |

값이 비면 빌더가 자리표시자로 덮어쓰고 경고를 낸다(서식 예시 내용이 제출본에
남는 것을 막기 위해서다).

## 조문

```json
"본칙": [{"level": "조", "text": "제1조(목적) 이 조례는 …"}],
"부칙": [{"level": "조", "text": "제1조(시행일) 이 조례는 공포한 날부터 시행한다."}]
```

`level`은 제목 `장·절`과 조문 `조·항·호·목·1)·가)·(1)·(가)` 8단계. 장·절 제목은 **각각 독립 항목**이다
(제1조 앞의 `제1장`+`제1절` 두 줄 모두 보존, 본칙 중간의 장·절도 앞 항에 붙이지 않는다). **앞 공백은 빌더가 서식별로 붙이므로
넣지 않는다.** `text`에는 번호·기호(제1조, ②, 1., 가.)를 포함한다.

## 입법예고 전용

| 키 | 타입 | 설명 |
|---|---|---|
| `공고번호` | str | `제2026-100호` |
| `공고일` | str | `2026. 08. 20.` |
| `제출기한` | str | `2026년 9월 3일(목)까지` |
| `문의처` | str | `○○과 031)8008-1234` 형태 (`○ 경기도의회 ` 는 빌더가 붙인다). 파서 기본값은 눈에 보이는 자리표시자 `○○○과 031)8008-○○○○`이며 `_미확정`에 오른다 — 가짜 번호를 실제처럼 찍지 않는다 |
| `관계법령` | obj[] | `[{"법령명":"고등교육법","조문":[{"level":"조","text":"…"}]}]` |

### 개정조례일 때 추가 필수 (입법예고 + 완성본·표준서식의 대비표)

| 키 | 타입 | 설명 |
|---|---|---|
| `현행조례명` | str | 「」 없이. 두문(`「○○ 조례」 일부를 다음과 같이 개정한다.` / 전부개정은 `… 전부를 …`)은 **빌더가** 이 값과 `유형`으로 만든다. 파서는 원문의 두문 줄에서 뽑고, 두문이 없으면 제명에서 추정해 `_미확정`에 올린다 |
| `개정문` | obj[] | **두문 다음 줄부터 부칙 전까지** — 지시문(`제○조제○항 중 “…”를 “…”로 한다.`, 괄호 없는 지시문·`같은 조 …` 포함)과 신설 조문 본문. **두문 줄 자체는 넣지 않는다**(들어 있으면 빌더가 걷어낸다). 지시문 줄의 level은 `조`. 하위호환으로 `본칙`은 `개정문`과 같게 둔다 |
| `대비표` | [str,str][] | `[["현행 조문","개정안 조문"], …]`. 셀 안 줄바꿈은 `\n`. 바뀐 자구는 `〔U〕…〔/U〕`로 감싸면 세 빌더(입법예고 build_yego, 완성본 build_uian, 표준서식 build_ordinance)가 모두 밑줄로 찍고 표식은 지운다(한 줄 안에서 짝을 맞출 것). **완성본·표준서식에도 쓰인다**(부칙 뒤 새 쪽, 2026-10-02) |
| `현행조례` | obj[] | 참고 1에 실을 현행 조례 전문 — `law-search`로 조회 |

대비표 관행: 변경 없음 = `(생  략)` / `(현행과 같음)`, 자구 수정은 바뀐 부분만 쓰고
나머지는 줄표(`----`), 신설은 `<신  설>` / 새 조문 전문.

## 서명부 전용

| 키 | 타입 | 설명 |
|---|---|---|
| `공동발의` | str[] \| obj[] | `"수원1\|김철수"` 또는 `{"소속":"수원1","성명":"김철수"}` |
| `서명부쪽수` | int | 미지정 시 인원수로 자동 산정(15명/쪽, 인원 0이면 2쪽) |

서명 열은 손서명용이라 **항상 공란**이다.

## 메타

| 키 | 설명 |
|---|---|
| `_미확정` | 파서가 못 채운 항목(스펙 키) 목록 — 사용자에게 한 번에 모아 묻는 근거. 소관위원회·문의처·공고번호 등 자리표시자 값도 포함 |
| `_경고` | 파서 경고 — 부칙 수집을 붙임 경계에서 멈춤, 부칙 20문단 초과, 두문 추정 등 |
| `_원본` | 스펙을 뽑아낸 원본 파일 경로 |

## 파서 경계 규칙 (2026-10-12)

- 부칙(조문만 있는 파일은 본칙도) 수집은 **붙임 경계**에서 멈춘다: 줄머리 `[별표`·`[별지`·`붙임`/`덧붙임`, 그리고 조문 마커가 아닌 줄의 `비용추계`·`관계법령 발췌`·`신ㆍ구조문`·`검토의견`·줄머리 `입법예고`·`참고 N`.
- HWPX의 표(`hp:tbl`) 글자는 본문으로 읽지 않는다(의안 표지의 발의연월일·발의자 메타데이터 검색에만 쓴다).
- 부칙이 20문단을 넘으면 `_경고`에 남긴다.
