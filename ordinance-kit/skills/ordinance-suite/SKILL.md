# 조례안 문서 4종 일괄 생성 (ordinance-suite)

조례안 하나에서 발의 서류 전부를 만든다. **서식마다 규격이 다르므로**(의안 규격
≠ 표준 입안 규격) 직접 조판하지 않고 담당 스킬의 빌더를 호출한다.

| # | 산출물 | 담당 스킬 | 규격 |
|---|---|---|---|
| 1 | 조례안 완성본(의안 서식) | `ordinance-uian` | 조 27.28 / 항·호 29.92pt |
| 2 | 조례안 표준 입안 서식 | `ordinance-format` | 조 14 / 호 24.4 / 목 45.4pt |
| 3 | 입법예고 의뢰서 | `ipbeop-yego` | 법제과 2025-08-12 배포본 |
| 4 | 발의의원 서명부 | `signature-sheet` | 쪽당 15명, 서명란 공란 |

의존 스킬 4개가 `~/.claude/skills/` 아래 함께 설치돼 있어야 한다(다른 PC 이식은
`install/` 참조). 한/글이 설치된 Windows에서만 동작한다.

## 1단계 — 스펙 추출

```bash
python scripts/parse_ordinance.py "조례안.hwpx" suite.json --대표발의 홍길동
```

조례안 완성본이면 제안이유·주요내용·참고사항·발의자까지, 조문만 있는 파일이면
조문 계층만 뽑는다. **없는 값을 지어내지 않는다** — 못 채운 칸은 `_미확정`에
남으며, 그 목록을 사용자에게 **한 번에 모아 묻는다.**

빠지기 쉬운 항목과 확인 방법:

| 항목 | 쓰이는 곳 | 확인 |
|---|---|---|
| 소관위원회·대표발의 | 입법예고 예고문 | 사용자에게 확인 |
| 공고번호·공고일·제출기한 | 입법예고 공고문 | 미정이면 빈칸형 유지 가능 |
| 관계법령 발췌 | 입법예고 참고 | 상위법 조문 — `law-search`로 원문 확인 |
| 공동발의 의원 명단(소속·성명) | 서명부 | 소속 열에 지역구/정당/상임위 중 무엇을 넣을지, 대표발의 의원을 1번에 넣을지 **관행이 갈리므로 반드시 확인** |
| (개정) 현행 조례 전문·신구조문 대비표 | 입법예고 참고 1·대비표 | `law-search`로 현행 조례 조회 |

발의 정족수는 의회 회의규칙마다 다르다 — **기억으로 단정하지 말 것.**

스펙 스키마 전체는 `references/spec-schema.md`, 예시는 `examples/example.suite.json`.

## 2단계 — 일괄 생성

```bash
python scripts/run_suite.py suite.json --outdir "출력폴더" --pdf
```

- `--only 완성본,입법예고` 로 일부만 만들 수 있다(이름: `완성본`·`표준서식`·`입법예고`·`서명부`).
- 한 서식이 실패해도 나머지는 계속 만들고 마지막에 성공/실패 표를 낸다. **실패한
  서식을 조용히 빼고 완료라고 하지 말 것.**
- 각 빌더의 스테이징 결과는 한/글 COM으로 정품 재저장된다(보안수준 '높음' 대응).
- `--pdf`를 주면 검증용 PDF가 작업폴더(`%TEMP%/ordsuite_*`)에 생긴다. 사용자에게는
  HWPX만 전달한다.

산출 파일명:

```
{조례명}(완성본)_{YYMMDD}.hwpx
{조례명}(표준서식)_{YYMMDD}.hwpx
입법예고 의뢰서_{조례명}_{YYMMDD}.hwpx
발의의원 서명부_{조례명}_{YYMMDD}.hwpx
```

### 개정조례일 때 — 현행 조례·대비표 자동 채움

`유형`이 일부개정·전부개정이면 입법예고 의뢰서에 **현행 조례 전문과 신·구조문
대비표가 필수**다. 이 둘은 국가법령정보센터 API에서 자동으로 받아올 수 있다.

```bash
python scripts/fetch_current.py suite.json --org 경기도 --inplace
```

- `현행조례` — 현행 조례 **전문**을 API 원문으로 채운다(참고 1에 그대로 실린다)
- `대비표` — **AST 엔진**이 개정 지시문을 편집 연산으로 컴파일해 현행 트리에 적용한 뒤,
  두 트리를 대비해 만든다. 자구 수정·제목 개정·항 승격·**신설·삭제·조번호 이동**이
  자동 반영된다. 개정안 열은 실무 관행대로 **바뀐 부분만 쓰고 나머지는 줄표**다.
  신설 조문 전문처럼 **사람이 써야 하는 것만** `[[TODO:…]]` 로 남는다.

지원하는 지시문 문형(자치법규입안길라잡이 2022 제3편 제2장 기준):

| 문형 | 처리 |
|---|---|
| `제○조제○항 중 “A”를 “B”로 한다` (복수 치환·`각각`) | 자구 수정 |
| `제○조의 제목 “(A)”를 “(B)”로 한다` | 제목 개정 |
| `제○조 제목 외의 부분을 제1항으로 한다` | 항 승격 |
| `제○조를(제○항을) 다음과 같이 신설한다` | 신설 |
| `제○조를 삭제한다` / `제○조부터 제○조까지를 각각 삭제한다` | 삭제 |
| `제4조부터 제6조까지를 각각 제5조부터 제7조까지로 한다` | **범위 재번호** |
| `제3조를 제3조의2로 한다` | **가지번호 이동** |
| `같은 조`·`같은 항`·`제6조(종전의 제5조)` | 대명사·재번호 후 지칭 |

`하고,`·`하며,`·`하여,` 로 이어진 복합 지시문은 절 단위로 나눠 **순서대로** 적용한다 —
재번호 뒤 절은 새 번호로 지칭하는 것이 실무 표기이기 때문이다.

**검증 상태** — 경기도의회 일부개정조례안 4건(대비표 58행)으로 교차 검증했다.

| 샘플 | 지시문 해석 | 행수 | 셀 일치 |
|---|---|---|---|
| 6번 | 2연산 · 경고0 오류0 | 1/1 | **1/1** |
| 18번 | 1연산 · 경고0 오류0 | 2/2 | 1/2 |
| 19번 | 25연산 · 경고0 오류0 | 38/39 | 13/39 |
| 21번 | 13연산 · 경고0 오류0 | 16/16 | **14/16** |
| 합계 | **경고 0 · 오류 0** | **57/58** | 29/58 |

**지시문은 전부 해석·적용된다**(경고·오류 0). 남은 차이는 줄표 어절 경계 같은
**표기 세부**이고, 작성자 재량이 섞여 있어 완전 일치는 목표가 아니다.
**생성 결과는 초안이며 사람이 검토·손질하는 것을 전제로 한다.**

조례명이 여러 지자체에 있으면 `--org`로 좁힌다(예: 경기도 vs 경기도교육청).

### 미완성 차단 게이트

미완성 자리는 `[[TODO:신설조문]]` `[[TODO:개정안조문]]` 이라는 **검색 가능한 토큰**으로
남는다. 사람이 읽는 한글 문장으로 두면 본문과 섞여 검사에서 빠져나가고, **경고는 언젠가
무시된다.** 그래서 경고가 아니라 **빌드를 실패시킨다.**

| 게이트 | 시점 | 동작 |
|---|---|---|
| **G1** 정적검사 | `fetch_current.py` | 지시문이 고치라는 원문이 현행 조문에 **없으면 중단**(exit 1). 조번호 오기 신호다 |
| **G2** 커버리지 | `fetch_current.py` | 지시문 수 > 대비표 행 수면 경고 |
| **G3** 센티널 | `run_suite.py` | `[[TODO:` 가 남아 있으면 **그 서식만 실패**시키고 위치를 지목한다 |

```
 입법예고   실패   미완성 표시 1건 — 채운 뒤 다시 실행하십시오.
                  대비표[1][1]  [[TODO:신설조문]] ← 제30조를 다음과 같이 신설한다.
 서명부    OK    …
```

초안 회람용이면 `--allow-todo` 로 통과시킬 수 있다(이때는 완료 후 경고를 다시 낸다).
**기본은 차단이다** — 플래그를 주지 않으면 미완성 문서는 만들어지지 않는다.

서식별로 실제 쓰는 필드만 검사하므로, 대비표가 미완성이어도 서명부·완성본은 정상 생성된다.

## 3단계 — 검증 (통과 전에는 완료라고 하지 않는다)

빌더가 자동으로 막는 것: 서식 정본의 자리표시자(`○○○○`) 잔존,
빨간 안내문·안내 박스 잔존, 조문 번호 불일치.

**PDF를 이미지로 렌더해 육안으로** 볼 것 — 잘림·겹침은 텍스트 검사로 안 잡힌다.

```bash
python -c "import pypdfium2 as p; d=p.PdfDocument('verify.pdf'); [d[i].render(scale=1.3).to_pil().save('p%d.png'%(i+1)) for i in range(len(d))]"
```

| 서식 | 볼 것 |
|---|---|
| 완성본 | 제명·대표발의·발의자 실제 값 / 주요내용·참고사항 항목 들여쓰기가 항목마다 동일 / 부칙이 새 쪽 |
| 표준서식 | 신명조 적용 / 조·호·목 내어쓰기 단계 / 제명 가운데 진하게 |
| 입법예고 | 빨간 안내문 0건 / 안내 박스 제거 / 의견제출 박스·참고 라벨 유지 / (개정) 대비표 좌우 대응 |
| 서명부 | 연번이 쪽을 넘어 이어짐 / **서명 열이 전부 공란** / 쪽수 = ceil(인원/15) |

자리표시자(`(관계 법령 조문을 …)`·`(현행 조례 전문을 …)`)가 찍혀 나온 서식은
**제출 전 반드시 채워야 한다** — 빌더가 경고로 알려주므로 그대로 사용자에게 전달한다.

## 파이프라인 밖의 일

- 조문 자체의 기획·설계 → `ordinance-draft`
- 상위법 저촉·중복 조례·비용추계 등 내용 검토 → `ordinance-review`
- 법령·판례 실재 확인 → `law-search` (인용 조례 제명은 가운뎃점 문자까지 대조)
