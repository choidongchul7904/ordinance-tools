# 조례 표준 서식 HWPX (ordinance-format)

법령 입안 실무의 「조례만들기(서식)」 가이드 규격을 그대로 구현한 스킬.
한글(HWP) COM으로 **정품 저장**하므로 재패키징·네임스페이스 후처리가 필요 없고,
한글 보안수준 '높음'에서도 경고 없이 열린다.

## 서식 규격

| 요소 | 서식 |
|---|---|
| 공포번호행 | `○○시·도(시·군·구)조례  제        호` — 신명조 14pt, 왼쪽 |
| 제명 | 가운데 정렬, 신명조 16pt, **진하게** |
| 본칙 조문 | 신명조 14pt, 양쪽정렬, 첫 줄 내어쓰기 |
| 부칙 제목 | `부      칙` (부+공백6+칙) — 가운데, 14pt, **진하게** |

**조·항·호·목 내어쓰기 7단계** (앞 공백은 스크립트가 자동 부여). `장`·`절` 레벨(제N장 …/제N절 …)은
내어쓰기 없이 **가운데 진하게** 문단으로 찍고 앞뒤에 빈 줄 1개를 둔다(맨 앞에 와도 빈 줄이 겹치지 않음).
허용 레벨은 아래 표 + `장`·`절`뿐이며, 그 밖의 레벨이나 `text` 누락은 오류로 중단한다(2026-10-12):

| 레벨 키 | 예 | 앞 공백 | 내어쓰기 |
|---|---|---|---|
| `조` | 제1조(목적) ① … | 0칸 | 14pt |
| `지시` | 제3조제1항 중 "…"를 "…"로 한다.(개정문 지시 줄·두문) | 0칸 | 14pt |
| `항` | ② … | 2칸 | 14pt |
| `호` | 1. … | 2칸 | 24.4pt |
| `목` | 가. … | 4칸 | 45.4pt |
| `1)` | 1) … | 6칸 | 54.2pt |
| `가)` | 가) … | 8칸 | 75.2pt |
| `(1)` | (1) … | 10칸 | 87.8pt |
| `(가)` | (가) … | 12칸 | 108.8pt |

> ※ `(가)` 108.8pt는 원본 가이드 PDF에서 수치가 잘려 있어 동일 유형 간 +21pt
> 등차 패턴(1.→가., 1)→가) 모두 +21pt)으로 추정한 값. 기관 확정 기준이
> 다르면 `scripts/build_ordinance.py`의 `LEVELS`만 고치면 된다.

## 사용법

### A. 빈 서식 템플릿 요청 ("조례 서식/템플릿 만들어줘")

```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_ordinance.py" --template "출력경로.hwpx"
```

검증 완료된 `assets/ordinance-template.hwpx`를 복사한다(COM 불필요, 즉시 완료).
템플릿은 2쪽 구성 — 1쪽 조례안 골격(공포번호행·제명·본칙·부칙), 2쪽 내어쓰기
기준표(각 단계가 실제 문단 서식으로 적용된 견본. 복사해 쓰면 서식 유지).

### B. 조문 내용을 표준 서식으로 조판

spec JSON을 만들어 실행한다:

```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_ordinance.py" spec.json
```

```json
{
  "output": "출력폴더\\경기도_○○_조례안.hwpx",
  "title": "경기도 ○○ 지원 조례안",
  "promulgation_line": "경기도조례  제        호",
  "body": [
    {"level": "장", "text": "제1장 총칙"},
    {"level": "조", "text": "제1조(목적) 이 조례는 …함을 목적으로 한다."},
    {"level": "조", "text": "제2조(정의) ① 이 조례에서 사용하는 용어의 뜻은 다음과 같다."},
    {"level": "호", "text": "1. \"○○\"란 …를 말한다."},
    {"level": "목", "text": "가. …"},
    {"level": "항", "text": "② …"}
  ],
  "addenda": [
    {"level": "조", "text": "제1조(시행일) 이 조례는 공포한 날부터 시행한다."}
  ]
}
```

- 각 항목의 `text`에는 번호·기호(제1조, ②, 1., 가. 등)를 **포함해서** 쓴다.
  앞 공백은 레벨에 따라 스크립트가 자동으로 붙이므로 넣지 않는다.
- `promulgation_line` 생략 시 기본값 `○○시·도(시·군·구)조례  제        호`.
- `addenda`가 있으면 `부      칙` 제목이 자동 삽입된다.
- `"pdf_preview": true`를 넣으면 같은 이름의 확인용 PDF도 함께 저장된다.
- **개정조례안**: `"compare_table": [["현행 셀", "개정안 셀"], …]`(셀 안 줄바꿈 `\n`, 바뀐 자구는
  `〔U〕…〔/U〕`)를 주면 부칙 뒤 새 쪽에 「신ㆍ구조문대비표」가 붙는다(2026-10-02). 표는
  `ordinance-uian/scripts/compare_table.py`(경기도의회 의안 제1621호 실물 규격: 머리행 사방 테두리,
  줄 단위 행에 가로선 없음, 조 내어쓰기 14pt·항ㆍ호 24.4pt)를 **신명조**로 이식한 것이고, 삽입 뒤
  한/글 COM으로 다시 정품 저장한다(COM 2회). ordinance-suite가 `대비표`를 이 키로 넘긴다.
  `compare_title`로 제목을 바꿀 수 있다. ordinance-uian 스킬이 없으면 이 키는 오류다.
  대비표 셀에 미검증 마커가 있으면 중단하지 않고 **그 셀만 공란**으로 두고 보고한다. 목 이하 줄은
  머리 기호로 계층을 판별해 앞 공백·내어쓰기를 유지하고, 표가 쪽을 넘으면 머리행이 반복된다.
  > 규격 혼용에 관한 주의: 대비표는 **의도된 예외**다. 표 자체는 의안 실물(제1621호)의 규격을 그대로
  > 이식한다(표 셀 안의 문단모양이라 본칙 문단과 섞이지 않는다).
  > 본칙 조판에 의안 서식(ordinance-uian)의 13.64/14.96pt 값을 섞지 말라는 원칙은 그대로다.
- **개정조례안(일부개정·전부개정)** (2026-10-12): 유형은 제명에서 자동 판별한다(공백을 모두 지운 뒤
  `전부개정`→전부개정, `일부개정` 또는 `…개정조례안/개정규칙안`으로 끝나면→일부개정, 그 밖→제정).
  `"유형"`(또는 `"type"`)을 주면 그 값이 우선하지만, 제명이 개정인데 값이 다르면 중단한다.
  `"현행조례명"`(「」 없이)과 `"개정문"`(두문을 뺀 지시 줄+삽입 조문, 없으면 `body`)을 주면 빌더가
  두문 `「현행조례명」 일부를 다음과 같이 개정한다.`(전부개정은 `전부를`)를 첫 줄로 찍는다.
  `개정문` 첫 줄이 이미 두문이면 다시 붙이지 않는다(옛 spec 호환). 현행조례명이 없으면 제명에서 추정하고 경고한다.
  영문 별칭 `current_title`·`amendment`도 받는다.
- 조문 원문을 확인하지 못한 항목은 `text`에 확인 실패 사유를 문장으로 풀어 쓰지 말고
  `[원문 미확인]`/`[확인 필요]` 마커를 넣을 것. `build_ordinance.py`가 이를 감지해 완성본
  에서는 그 조항을 **들여쓰기 없는 빈 줄**로 처리하고, 원문은 stdout에 `[미검증 ...]` 목록으로만 출력한다
  (대화창 보고 전용 — 문서에는 절대 남기지 않는다). 마커 없이 쓰면 그대로 노출된다.
  마커 잔존 검사는 한/글을 띄우기 **전에** 한다(fail fast).

### 검증 (스크립트가 자동 수행, 실패 시 종료코드 1)

1. 조판 명령(rows)·대비표 셀의 미검증 마커 검사 — COM 실행 전
2. 한글 COM으로 생성 → 임시 폴더에 stage 저장 (최종 경로 직접 저장 금지 — 파일 잠금 방지)
3. stage HWPX를 zip으로 열어 검사: 신명조 등록 여부, **문단마다** 내어쓰기가 그 줄의 레벨 값과 같은지
   (값이 '어딘가 있다'가 아니라 1:1 대조), 문단 텍스트 불일치는 경고
4. SaveAs 반환값·산출 파일 존재 확인 후 최종 경로로 복사

회귀 테스트(COM 없이): `python "${CLAUDE_SKILL_DIR}/tests/test_format.py"` — 전부 통과해야 exit 0.

레이아웃이 중요한 문서(표 포함·쪽수 제한 등)는 추가로 PDF를 pypdfium2로
렌더해 육안 확인할 것 — 잘림·겹침은 텍스트 검사로 잡히지 않는다.

## 이 PC 검증 사항 (스크립트에 이미 반영됨)

- `HParameterSet` 속성 대입이 조용히 깨져 있다 — 반드시
  `CreateAction → CreateSet → GetDefault → SetItem → Execute` 경로 사용.
- CharShape의 FaceName은 `FontType*=1`(TTF)을 함께 SetItem해야 적용된다.
  신명조는 이 PC에 TTF로 존재함(header.xml에 `신명조 TTF`로 등록되는지 확인).
- COM `Open`/`SaveAs`는 실패해도 예외 없이 False만 반환 — 반환값을 반드시 검사.
- `Indentation` 음수 = 내어쓰기, 단위는 **pt×200**(글자 `Height`의 pt×100과 다르다). 2026-10-12 실측:
  pt×100으로 넣었더니 한/글이 표준 값의 정확히 절반(조 7pt·호 12.2pt…)으로 그렸다. 지금 값(조 -2800·호 -4880·
  목 -9080·1) -10840·가) -15040·(1) -17560·(가) -21760)으로 PDF를 재면 둘째 줄이 여백에서
  14·24.4·45.4·54.2·75.2pt — 「조례만들기(서식)」과 일치. `AlignType` 3 = 가운데.
- 출력 경로(`output`)를 지정받지 못하면 환경변수 `ORDINANCE_OUT_DIR`, 그것도 없으면
  `출력폴더`에 저장.
- 조문 내용의 기획·작성은 ordinance-draft, 검토는 ordinance-review·ordinance-lint가 맡고,
  이 스킬은 완성된 조문의 서식 조판만 담당한다. 발의 서류 4종(완성본·표준서식·입법예고·서명부)을
  한 번에 만들려면 ordinance-suite를 쓴다.
- 인터페이스·소비/역의존 관계는 `CONTRACT.md`.
