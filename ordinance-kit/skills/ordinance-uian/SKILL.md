# 조례안 완성본(의안 서식) HWPX

의원이 조례안을 발의할 때 의회에 제출하는 **의안(議案) 서식** 완성본을 만든다.
서식 정본은 `assets/uian-template.hwpx`에 내장돼 있다 — 실물 의안 완성본에서
서식·문단 구조만 남기고 내용은 `○○` 자리표시자로 비운 빈 골격이다.

> ⚠ **표준 입안 서식과 다른 규격이다.** 「조례만들기」 표준은 내어쓰기가
> 조 14 / 호 24.4 / 목 45.4pt인데, 이 의안 서식은 **조 27.28 / 항·호 29.92pt**를
> 쓴다. 의안(발의) 단계는 이 규격, 법제과 조판·공포 단계는 표준 규격이라는
> 이원 체계다. **본칙(조문) 조판에 두 규격을 섞지 말 것.**
>
> **예외 — 신ㆍ구조문대비표**: 개정조례안 끝의 대비표는 조 14pt·호 24.4pt(표준 계열)로 찍힌다.
> 이것은 혼용 실수가 아니라 **의도된 예외**다. 경기도의회 실물 의안 제1621호의 대비표가 바로 그 값이고,
> 빌더는 그 표를 잘라낸 자산(`assets/compare-table-template.hwpx`)을 그대로 이식한다.

## 문서 구조

```
section0  제1부 — 의안 표지 + 제안설명서
  제명(HY견고딕 20pt) / (○○○ 의원 대표발의) / [표] 의안번호·발의연월일·발의자
  1. 제안이유   2. 주요내용(가.~, 끝에 "(안 제○조)")   3. 참고사항(가.~마.)
section1  제2부 — 조례안 본문 (새 쪽에서 시작)
  ○○ 조례  제   호 / 제명 / 제1조~ / 부      칙
  (개정조례안) 신ㆍ구조문대비표 — 부칙 뒤 새 쪽 (2026-10-02)
```

### 개정조례안의 신ㆍ구조문대비표 (자동)

유형이 일부개정·전부개정(아래 「개정조례안 본칙」의 판별 규칙)이고 `대비표`가 있으면, 부칙 뒤
새 쪽에 「신ㆍ구조문대비표」를 붙인다(`scripts/compare_table.py`). 서식 정본은
`assets/compare-table-template.hwpx` — 경기도의회 **의안 제1621호**(경기도 청소년 보호 및
육성에 관한 조례 일부개정조례안, 2025.1.) 실물에서 잘라낸 표다.

| 요소 | 실물 규격 |
|---|---|
| 제목 | `신ㆍ구조문대비표` 가운데 16pt 진하게, 새 쪽 |
| 머리행 | `현        행` / `개   정   안` 사방 테두리, 가운데 |
| 본문 | **줄 단위 행**(가로선 없음, 좌우선만). 조 줄 내어쓰기 14pt·180%, 항ㆍ호 줄 앞 공백 2칸·내어쓰기 24.4pt. 좌우 줄이 1:1로 맞물리며 조 사이 빈 행 1개 |
| 마감 | 머리행 밑 간격행(283)·마지막 아래선 행 |
| 밑줄 | 셀 텍스트의 `〔U〕…〔/U〕` 안쪽만 밑줄 run, 표식은 제거 |

- `대비표`는 ordinance-suite spec과 같은 `[["현행 셀","개정안 셀"], …]`(셀 안 줄바꿈 `\n`).
  `fetch_current.py`가 만든 것을 그대로 쓰면 된다. 좌우 줄 수가 다르면 짧은 쪽을 빈 줄로 채운다.
- 참고사항을 비우면 개정조례안 기본값은 실물대로 `가. 신ㆍ구조문 대비표: 덧붙임`으로 시작한다.
- `--compare off`로 끌 수 있다. 제정조례안(`유형` 제정)은 `대비표`가 있어도 붙이지 않고 경고만 낸다.
- 이식 함정(실측): 자산의 글자모양ㆍ문단모양ㆍ테두리ㆍ글꼴을 대상 header **목록 끝**에 복사하고
  새 id는 **최대 id+1**로 잡는다(borderFill은 id가 1부터라 itemCnt를 쓰면 마지막 id와 충돌해
  호 줄에 글자 테두리가 그려진다). 문단모양 안의 `hh:border borderFillIDRef`도 재매핑해야
  세로선이 행마다 끊기지 않는다. 행은 remap을 **한 번만** 거친다(두 번 하면 대상 id를 자산 id로 오인).
- 검증: `verify_block`이 표식·마커 잔존 0건과 행 수(2+줄 수 합+조 간격+1)를 확인한다. 쪽수는 표 길이만큼 는다.
- (2026-10-12) 셀에 미검증 마커가 있으면 **빌드를 멈추지 않고 그 셀만 공란**으로 두고 `[미검증 …]`으로 보고한다.
  목·1)·가)·(1)·(가) 줄은 머리 기호로 계층을 판별해 앞 공백(4/6/8/10/12칸)과 계층별 내어쓰기(표준 계열
  45.4/54.2/75.2/87.8/108.8pt — 1621호엔 목 이하 실례가 없어 표준값 차용)를 쓴다. 표가 쪽을 넘으면
  머리행이 반복된다(`repeatHeader="1"` + 머리행 셀 `header="1"`). 표 id는 내용의 crc32로 결정적이다.
- 제목은 기본 `신ㆍ구조문대비표`(ㆍ U+318D — 자산=1621호의 표기). spec `대비표제목`(또는 compare_table
  `--title`)으로 바꿀 수 있다. 참고사항 기본값 `가. 신ㆍ구조문 대비표: 덧붙임`의 가운뎃점은 **실물 1621호
  원문과 대조하지 못했다** — 제출 전 실물과 맞출 것(추측으로 바꾸지 않음).

## 사용법

```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_uian.py" spec.json stage.hwpx            # [--buchik-break on] [--compare off] [--keep-newnum]
python "${CLAUDE_SKILL_DIR}/scripts/compare_table.py" in.hwpx out.hwpx suite.json --section 1   # 대비표만 따로 붙일 때(스테이징)
python "${CLAUDE_SKILL_DIR}/scripts/com_save.py" stage.hwpx "출력폴더/○○ 조례안(완성본)_260807.hwpx" verify.pdf
python "${CLAUDE_SKILL_DIR}/scripts/align_notes.py" stage.hwpx verify.pdf           # 참고사항 [붙임 N] 점선 정렬(보정 있으면 exit 1)
python "${CLAUDE_SKILL_DIR}/scripts/com_save.py" stage.hwpx "<최종경로>.hwpx" verify.pdf  # 보정이 있었을 때만 재저장
```

- `align_notes.py`: PDF에서 `[붙임 N]` 오른쪽 끝을 재서 하이픈 수를 보정한다(하이픈 1개 = 7.001pt, 목표 x≈538pt).
  줄이 넘쳐 두 줄이 되면 그 줄만 양쪽정렬로 늘어나 측정이 왜곡되므로 넘침부터 줄인다. 보정 0건이 될 때까지 최대 2회.
- `--buchik-break`: 기본 `off` = 기준선처럼 마지막 조문 뒤 빈 줄 하나를 두고 부칙이 이어진다. `on`은 항상 새 쪽(부칙만 있는 쪽이 하나
  늘어 5쪽짜리가 6쪽이 된다). `com_save.py`가 찍는 `PageCount`를 기준선과 대조해 확인한다.

- `--keep-newnum`: 표지 '발의연월일' 칸의 [새 번호 지정] 조판부호를 남긴다(기본은 제거 — 아래 편집 함정).
- `com_save.py`(2026-10-12): 같은 폴더 임시 파일에 저장 → 크기 확인 → `os.replace`로 교체하므로 저장이
  실패해도 **이전 정상 산출물이 남는다**. 한/글은 try/finally로 반드시 종료, 실패 시 exit≠0, PDF 실패는
  stderr 경고만. 사본 4개(ordinance-uian·ordinance-suite·ipbeop-yego·signature-sheet)는 바이트 동일해야 한다.
- 회귀 테스트(COM 없이): `python "${CLAUDE_SKILL_DIR}/tests/test_uian.py"` — 전부 통과해야 exit 0.

`com_save.py`를 건너뛰면 한/글 보안수준 '높음'에서 **변조 문서로 판정돼 열리지
않는다.** 스테이징은 스크래치패드에서 하고, 최종 경로에서 직접 빌드하지 말 것
(한/글이 파일을 잡으면 다음 빌드가 `PermissionError [WinError 32]`).

### spec.json

```json
{
  "조례명": "경기도 ○○ 지원 조례안",
  "공포기관": "경기도",
  "대표발의": "홍길동",
  "발의연월일": "2026년 08월    일",
  "발의자": "홍길동",
  "공동발의": ["김○○", "이○○", "박○○", "최○○"],
  "제안이유": ["배경·필요성 문단", "이 조례는 …함을 목적으로 함."],
  "주요내용": ["가. …을 규정함(안 제3조).", "나. …(안 제5조)."],
  "참고사항": ["가. 관계법령: 덧붙임", "..."],
  "본칙": [
    {"level": "장", "text": "제1장 총칙"},
    {"level": "조", "text": "제1조(목적) 이 조례는 …"},
    {"level": "항", "text": "② …"},
    {"level": "호", "text": "1. …"}
  ],
  "부칙": [{"level": "조", "text": "제1조(시행일) 이 조례는 공포한 날부터 시행한다."}]
}
```

개정조례안은 `본칙` 대신(또는 함께) 다음 키를 준다:

```json
{
  "조례명": "경기도 ○○ 지원 조례 일부개정조례안",
  "유형": "일부개정",
  "현행조례명": "경기도 ○○ 지원 조례",
  "개정문": [
    {"level": "지시", "text": "제3조제1항 중 “지원할 수 있다”를 “지원하여야 한다”로 한다."},
    {"level": "지시", "text": "제5조의2를 다음과 같이 신설한다."},
    {"level": "조", "text": "제5조의2(특례) …"}
  ],
  "대비표": [["현행 셀", "개정안 셀"]]
}
```

- `level`: `장·절·조·지시·항·호·목·1)·가)·(1)·(가)` — **앞 공백은 스크립트가 붙이므로 넣지
  않는다.** `text`에는 번호·기호(제1장, 제1조, ②, 1., 가.)를 포함해 쓴다. 이 밖의 레벨이나 `text`
  누락은 **오류로 중단**한다(예전엔 조용히 항 들여쓰기로 찍었다).
- `장`·`절`(또는 `제N장 …`/`제N절 …`으로 시작하는 조 줄, 단 `…다.`로 끝나는 개정 지시문 제외)은
  **같은 문서의 부칙 제목 paraPr·charPr를 빌려 가운데정렬**로 찍는다.
  다른 문서의 ID를 가져오면 서식이 어긋난다(실측). 앞뒤에 빈 줄 1개.
- 조 제목의 괄호가 겹쳐도(`제2조(정의(定義))`) 닫는 괄호까지만 진하게 찍는다.
- `목`·`1)`·`가)`·`(1)`·`(가)`는 header에 계층별 문단모양을 새로 추가해 쓴다(항ㆍ호 29.92pt 하나로 뭉개지
  않음). 값은 `references/template-spec.md` '목 이하 내어쓰기' — **추정값이라 한/글 육안 확인 필요**.
- 조문 번호 검증은 가지조(`제3조의2`)를 포함해 입력과 대조하고, 제정안은 순서(역전·건너뜀·본조 없는
  가지조)를 경고한다.

### 개정조례안 본칙(두문·개정문) — 2026-10-12

- **유형 판별**(ordinance-suite·ordinance-format과 공유 규약): 제명에서 공백을 모두 지운 뒤
  `전부개정` → 전부개정, `일부개정` 또는 `…개정조례안/개정규칙안`으로 끝나면 → 일부개정, 그 밖 → 제정.
  spec `유형`(제정/일부개정/전부개정)이 우선하지만, 제명이 개정인데 값이 다르면 **중단**한다.
- spec `현행조례명`(「」 없이)과 `개정문`([{level,text}] — **두문을 뺀** 지시 줄+삽입 조문)을 주면
  빌더가 두문을 본문 첫 줄로 찍는다: 일부개정 `「현행조례명」 일부를 다음과 같이 개정한다.`,
  전부개정 `「현행조례명」 전부를 다음과 같이 개정한다.` `개정문`이 없으면 `본칙`을 쓴다.
- 하위호환: `개정문`/`본칙` 첫 줄이 이미 두문(“다음과 같이 개정한다” 포함)이면 다시 붙이지 않는다.
  `현행조례명`이 없으면 제명에서 추정하고 경고한다(제출 전 공식 제명 대조).
- 두문·지시 줄(`지시`, 또는 머리 없는 `조`)은 조 문단모양에 진하게 없이 찍는다. 일부개정은 지시 줄
  사이에 빈 줄을 자동으로 넣지 않는다(전부개정은 제정처럼 조 사이 빈 줄 1개).
- `공동발의`(선택): 발의자 란을 실물 의안 규격으로 찍는다 — 대표발의자 선두, 서명부 순서대로 `·`(U+00B7,
  `ㆍ` 아님)로 잇고 한 줄 3명, 마지막 줄 `의원(N명)` 단독(2024.4.5. 경기도의회 상징물 조례안 표지 실측).
  `발의자`에 줄 목록을 직접 주면 그대로 쓴다. 발의연월일은 `2026년 8월 24일`처럼 0을 채우지 않는다.
- `참고사항` 생략 시 빈칸형 기본값(관계법령·입법예고·비용추계서·검토의견·예고결과)이
  들어간다. 실제 문서번호·일자는 **반드시 실물과 대조**할 것 — 기준선 원본이 다른
  안건의 절차 서류를 복사해 온 흔적이 있었다.
- `제안이유`·`주요내용`을 비우면 예시가 남지 않도록 자리표시자로 덮어쓰고 경고를
  출력한다.
- 조례안 파일에서 spec을 자동 추출하려면 `ordinance-suite/scripts/parse_ordinance.py`.

### 미검증(원문 확인 실패) 항목 — 절대 완성본에 설명 문장을 쓰지 않는다

법령·조문 원문을 확인하지 못한 채 `제안이유`·`주요내용`·`본칙`·`부칙`의 `text`를 채워야
하면, 확인 실패 사유를 그대로 문장으로 적지 말고 `[원문 미확인]`/`[확인 필요]` 마커를
텍스트에 포함시켜라. `build_uian.py`가 이 마커를 감지해 **그 항목을 완성본(의안 서식)에서
자동으로 빈 줄 처리**하고, 원문 전체를 stdout에 `[미검증 ...]` 목록으로 출력한다 — 이
목록은 반드시 대화창으로 사용자에게 보고하고, 문서에는 절대 다시 적지 않는다. 마커 없이
설명 문장만 쓰면 그대로 제출용 의안 문서에 노출된다.

## 자동으로 고치는 원본 서식 결함

기준선 파일을 그대로 복사하면 아래가 승계된다. 빌더는 모델 문단 1개로 통일해
이를 끊는다 — 직접 편집할 때도 같은 원칙을 지킬 것.

| 결함 | 처리 |
|---|---|
| 주요내용 가.~라.의 문단모양이 4종 제각각(내어쓰기 60.64/66/65.48/67.40pt) | 전부 paraPr 45로 통일 |
| 참고사항 다.·라.가 **배분정렬** — 줄이 짧으면 글자가 눌려 찍힌다 | 전부 paraPr 48(양쪽정렬)로 통일 |
| 제5조·제7조 각 호의 내어쓰기 0pt — 호가 길어지면 계층이 무너진다 | 모든 항·호에 29.92pt 적용 |
| 제1조만 줄간격 190%·자간 -2 | 조문 모델 하나(160%)로 통일 |

## 편집 함정 (실측 검증)

- 이 문서는 **스타일 기반이 아니라 직접 서식 기반**이다. 스타일을 적용하는 방식이
  아니라 **기존 문단을 복제해 글자만 교체**해야 서식이 유지된다.
- `section1[0]`의 run에 `hp:secPr`, `section1[1]`·`section0[0]`에 `hp:pageNum` ctrl이
  들어 있다. **그 run은 지우지 말고 안의 `hp:t`만 교체**할 것.
- 문단 인덱스는 표 안 문단을 포함한 **평탄화(`.//hp:p`) 순번**이다 — 발의연월일·
  발의자가 표지 표 셀 안에 있어 최상위 자식만 훑으면 잡히지 않는다.
- 텍스트를 바꾼 문단의 `<hp:linesegarray>`는 제거한다. 남기면 글자가 겹쳐 찍힌다.
- 부칙은 기준선대로 **쪽나눔 없이** 마지막 조문 뒤 빈 문단 1개 후 이어진다(`--buchik-break on`이면 새 쪽).
  부칙 제목은 기준선 실측대로 `부    칙`(공백 4칸 — 표준 입안 서식의 6칸과 다르다).
- **표지 [새 번호 지정] 함정**: 기준선 표지 표의 `발의연월일 :` 칸 run 안에 `<hp:ctrl><hp:newNum num="1"
  numType="PAGE"/></hp:ctrl>`(쪽 번호 새로 지정)이 숨어 있다. 완성본을 다른 문서의 붙임으로 복사하면 따라가
  그 지점에서 쪽번호가 1로 리셋된다(실물 완성본 실측). 빌더는 **기본으로 지우고** 개수를 stdout에
  찍는다(`--keep-newnum`이면 보존). 구역설정의 `hp:numbering newNum="1"` 속성은 다른 것이라 건드리지 않는다.
  직접 편집할 때는 그 칸에서 부호만 지우고, 쪽을 통째로 지우지 말 것(표지·제안설명서까지 날아간다).
- 말미에 **빈 쪽 1장이 남는 것은 기준선 원본도 동일**하다(관계법령 덧붙임 자리).

## 검증 (통과 전에는 완료라고 하지 않는다)

빌더가 자동으로 하는 것: 조문 번호(가지조 포함)가 입력과 일치하는지(표와 표를 품은 문단은 제외),
제정안 조문 순서, 서식 정본의 자리표시자(`○○○○`)가 남았는지, 미검증 마커 잔존 0건.

사람이 PDF 렌더로 볼 것:

```bash
python -c "import pypdfium2 as p; d=p.PdfDocument('verify.pdf'); [d[i].render(scale=1.3).to_pil().save('p%d.png'%(i+1)) for i in range(len(d))]"
```

- 제명·대표발의·발의자가 모두 실제 값인가
- 주요내용·참고사항 항목의 들여쓰기가 **항목마다 동일**한가(제각각이면 통일 실패)
- 참고사항에 눌려 찍힌 글자가 없는가(배분정렬 잔존 신호)
- 조문 번호가 1부터 빠짐없이 이어지고, 부칙이 마지막 조문 뒤 빈 줄 하나를 두고 이어지는가(쪽수를 기준선과 대조)
- 장 제목이 가운데정렬인가, 발의자 란이 3명/행·`의원(N명)` 규격인가, `[붙임 N]` 오른쪽 끝이 세 줄 모두 같은 x인가
- 목 이하 문단이 두 줄을 넘을 때 둘째 줄이 번호 뒤 글자에 맞는가(추정 내어쓰기 값 확인)
- 개정조례안: 두문이 한 번만 있는가, 대비표가 쪽을 넘을 때 머리행이 반복되는가

내용(중복 조례·상위법 근거·위임규정 누락)은 이 스킬의 소관이 아니다 —
`ordinance-suite`로 넘긴다.
