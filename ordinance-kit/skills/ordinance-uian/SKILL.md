# 조례안 완성본(의안 서식) HWPX

의원이 조례안을 발의할 때 의회에 제출하는 **의안(議案) 서식** 완성본을 만든다.
서식 정본은 `assets/uian-template.hwpx`에 내장돼 있다 — 실물 의안 완성본에서
서식·문단 구조만 남기고 내용은 `○○` 자리표시자로 비운 빈 골격이다.

> ⚠ **표준 입안 서식과 다른 규격이다.** 「조례만들기」 표준은 내어쓰기가
> 조 14 / 호 24.4 / 목 45.4pt인데, 이 의안 서식은 **조 27.28 / 항·호 29.92pt**를
> 쓴다. 의안(발의) 단계는 이 규격, 법제과 조판·공포 단계는 표준 규격이라는
> 이원 체계다. **두 규격을 한 문서에 섞지 말 것.**

## 문서 구조

```
section0  제1부 — 의안 표지 + 제안설명서
  제명(HY견고딕 20pt) / (○○○ 의원 대표발의) / [표] 의안번호·발의연월일·발의자
  1. 제안이유   2. 주요내용(가.~, 끝에 "(안 제○조)")   3. 참고사항(가.~마.)
section1  제2부 — 조례안 본문 (새 쪽에서 시작)
  ○○ 조례  제   호 / 제명 / 제1조~ / 부      칙
```

## 사용법

```bash
python scripts/build_uian.py spec.json stage.hwpx
python scripts/com_save.py stage.hwpx "출력폴더/○○ 조례안(완성본)_260807.hwpx" verify.pdf
```

`com_save.py`를 건너뛰면 한/글 보안수준 '높음'에서 **변조 문서로 판정돼 열리지
않는다.** 스테이징은 스크래치패드에서 하고, 최종 경로에서 직접 빌드하지 말 것
(한/글이 파일을 잡으면 다음 빌드가 `PermissionError [WinError 32]`).

### spec.json

```json
{
  "조례명": "경기도 ○○ 지원 조례안",
  "공포기관": "경기도",
  "대표발의": "홍길동",
  "발의연월일": "2026년 08월    일",
  "발의자": "홍길동",
  "제안이유": ["배경·필요성 문단", "이 조례는 …함을 목적으로 함."],
  "주요내용": ["가. …을 규정함(안 제3조).", "나. …(안 제5조)."],
  "참고사항": ["가. 관계법령: 덧붙임", "..."],
  "본칙": [
    {"level": "조", "text": "제1조(목적) 이 조례는 …"},
    {"level": "항", "text": "② …"},
    {"level": "호", "text": "1. …"}
  ],
  "부칙": [{"level": "조", "text": "제1조(시행일) 이 조례는 공포한 날부터 시행한다."}]
}
```

- `level`: `조·항·호·목·1)·가)·(1)·(가)` — **앞 공백은 스크립트가 붙이므로 넣지
  않는다.** `text`에는 번호·기호(제1조, ②, 1., 가.)를 포함해 쓴다.
- `참고사항` 생략 시 빈칸형 기본값(관계법령·입법예고·비용추계서·검토의견·예고결과)이
  들어간다. 실제 문서번호·일자는 **반드시 실물과 대조**할 것 — 기준선 원본이 다른
  안건의 절차 서류를 복사해 온 흔적이 있었다.
- `제안이유`·`주요내용`을 비우면 예시가 남지 않도록 자리표시자로 덮어쓰고 경고를
  출력한다.
- 조례안 파일에서 spec을 자동 추출하려면 `ordinance-suite/scripts/parse_ordinance.py`.

### 미검증(원문 확인 실패) 항목 — 절대 완성본에 설명 문장을 쓰지 않는다

법령·조문 원문을 확인하지 못한 채 `제안이유`·`주요내용`·`본칙`·`부칙`의 `text`를 채워야
하면, 확인 실패 사유를 그대로 문장으로 적지 말고 `[원문 미확인]`/`[확인 필요]` 마커를
텍스트에 포함시켜라. `build_uian.py`가 이 마커를 감지해 **그 항목을 완성본(의안 서식)에서
자동으로 빈 줄 처리**하고, 원문 전체를 stdout에 `[미검증 ...]` 목록으로 출력한다 — 이
목록은 반드시 대화창으로 사용자에게 보고하고, 문서에는 절대 다시 적지 않는다. 마커 없이
설명 문장만 쓰면 그대로 제출용 의안 문서에 노출된다.

## 자동으로 고치는 원본 서식 결함

기준선 파일을 그대로 복사하면 아래가 승계된다. 빌더는 모델 문단 1개로 통일해
이를 끊는다 — 직접 편집할 때도 같은 원칙을 지킬 것.

| 결함 | 처리 |
|---|---|
| 주요내용 가.~라.의 문단모양이 4종 제각각(내어쓰기 60.64/66/65.48/67.40pt) | 전부 paraPr 45로 통일 |
| 참고사항 다.·라.가 **배분정렬** — 줄이 짧으면 글자가 눌려 찍힌다 | 전부 paraPr 48(양쪽정렬)로 통일 |
| 제5조·제7조 각 호의 내어쓰기 0pt — 호가 길어지면 계층이 무너진다 | 모든 항·호에 29.92pt 적용 |
| 제1조만 줄간격 190%·자간 -2 | 조문 모델 하나(160%)로 통일 |

## 편집 함정 (실측 검증)

- 이 문서는 **스타일 기반이 아니라 직접 서식 기반**이다. 스타일을 적용하는 방식이
  아니라 **기존 문단을 복제해 글자만 교체**해야 서식이 유지된다.
- `section1[0]`의 run에 `hp:secPr`, `section1[1]`·`section0[0]`에 `hp:pageNum` ctrl이
  들어 있다. **그 run은 지우지 말고 안의 `hp:t`만 교체**할 것.
- 문단 인덱스는 표 안 문단을 포함한 **평탄화(`.//hp:p`) 순번**이다 — 발의연월일·
  발의자가 표지 표 셀 안에 있어 최상위 자식만 훑으면 잡히지 않는다.
- 텍스트를 바꾼 문단의 `<hp:linesegarray>`는 제거한다. 남기면 글자가 겹쳐 찍힌다.
- 부칙이 앞 조문과 쪽이 갈리면 부칙 제목 문단에 `pageBreak="1"`(빌더가 항상 적용).
- 말미에 **빈 쪽 1장이 남는 것은 기준선 원본도 동일**하다(관계법령 덧붙임 자리).

## 검증 (통과 전에는 완료라고 하지 않는다)

빌더가 자동으로 하는 것: 조문 번호가 입력과 일치하는지, 서식 정본의 자리표시자
(`○○○○`)가 남았는지.

사람이 PDF 렌더로 볼 것:

```bash
python -c "import pypdfium2 as p; d=p.PdfDocument('verify.pdf'); [d[i].render(scale=1.3).to_pil().save('p%d.png'%(i+1)) for i in range(len(d))]"
```

- 제명·대표발의·발의자가 모두 실제 값인가
- 주요내용·참고사항 항목의 들여쓰기가 **항목마다 동일**한가(제각각이면 통일 실패)
- 참고사항에 눌려 찍힌 글자가 없는가(배분정렬 잔존 신호)
- 조문 번호가 1부터 빠짐없이 이어지고, 부칙이 새 쪽에서 시작하는가

내용(중복 조례·상위법 근거·위임규정 누락)은 이 스킬의 소관이 아니다 —
`ordinance-review`로 넘긴다.
