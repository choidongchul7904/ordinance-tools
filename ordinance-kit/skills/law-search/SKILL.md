# law-search — 현행 법령·판례 검색 (국가법령정보 Open API)

법제처 국가법령정보 공동활용 Open API(`law.go.kr/DRF`)를 감싸, **현행 법령·판례를 실시간으로 검증·인용**한다.
반환되는 시행일자·공포일자·조문 원문을 그대로 인용하면 근거가 검증 가능해진다(허위 인용 차단).
가이드: https://open.law.go.kr/LSO/openApi/guideList.do · OC(기관코드)는 **환경변수 `LAW_OC`** 로 지정(open.law.go.kr 에서 무료 발급).

## 명령 (scripts/lawsearch.py)
```
python scripts/lawsearch.py search --target law  --query "저작권법"     # 현행법령 검색
python scripts/lawsearch.py search --target prec --query "저작권"        # 판례 검색
python scripts/lawsearch.py law    --mst <법령일련번호> [--jo 25] [--jo 7의2]  # 법령 본문/특정 조문
python scripts/lawsearch.py law --target ordin --mst <자치법규일련번호> [--jo 3]  # 조례·규칙 본문/조문
python scripts/lawsearch.py prec   --id <판례일련번호>                    # 판례 본문
```
- `search` → `{total, results[]}`. 법령 결과: 법령명한글·법령ID·**법령일련번호(MST)**·공포일자·시행일자·소관부처명.
  판례 결과: 사건명·법원명·선고일자·사건번호·**판례일련번호**.
- `law --mst <MST>` → 법령명·공포일자·시행일자·소관부처 + **조문[]**. 조문 하나는
  `조문번호`·`조문가지번호`·`조문제목`·`조문여부`·`조문내용`(조 제목줄)·**`조문원문`**(항·호·목까지 펼친 전문)·
  **`항[]`**(항번호·항내용·`호[]`(호번호·호내용·`목[]`)) 를 갖는다. **인용은 `조문원문`/`항[]` 을 쓴다** —
  항이 있는 조는 `조문내용`이 조 제목뿐이다.
- `--jo` 는 본조만 정확히 집는다: `--jo 7`→제7조(제7조의2 제외), `--jo 7의2`→제7조의2. 장·절 제목(`조문여부='전문'`)은 제외.
- `law --target ordin` → 자치법규(조례·규칙) 본문. 응답 구조가 법령과 달라(`LawService > 조문 > 조[]`,
  필드는 `조제목`·`조내용`뿐이고 항·호가 분리돼 있지 않다) 스크립트가 법령과 같은 모양으로 정규화한다.
  조번호는 `조문번호`(`['000100','000100']`) 인코딩을 믿지 말고 **본문 머리에서 파싱**한다.
- `target`: `law`(현행법령)·`eflaw`(시행일법령)·`prec`(판례)·`detc`(헌재결정례)·`expc`(법령해석례)·`admrul`(행정규칙)·`ordin`(자치법규).

## 전형적 흐름 (조례안 근거 확보)
1. `search --target law --query "저작권법"` → 현행 여부·MST·시행일자 확인.
2. `law --mst <MST> --jo <조>` → 인용할 **조문 원문** 확보 → 그대로 인용(예: "저작권법(시행 2026.5.11.) 제2조").
3. `search --target prec --query "..."` → 판례 검색 → `prec --id <일련번호>` 로 판시사항 확보.
4. `search --target ordin --query "경기도 ○○ 조례"` → `law --target ordin --mst <MST>` 로
   **현행 조례 전문** 확보 → 입법예고 의뢰서의 참고 1·신·구조문 대비표 원본으로 쓴다.

## 조례 스킬 연계 (핵심 용도)
- **ordinance-suite**: `fetch_current.py` 가 이 스킬로 현행 조례를 받아 개정 지시문을 적용하고
  대비표를 만든다. 조회가 실패하면 대비표를 지어내지 않고 중단한다.
- **조례 검토**: 인용한 상위법 조문이 실재·현행인지, 시행일자가 맞는지 대조한다 —
  해소되지 않은 인용은 `[확인 필요]` 로 남긴다.

## 우아한 강등
네트워크·API 오류 시 exit 3 + 오류 메시지를 낸다(조용히 통과 금지). 이 경우 해당 인용은 `[확인 필요]` 로 두고
"국가법령정보센터에서 수동 확인" 을 안내한다. 근거를 지어내지 않는다.

**exit 2(결과없음)와 exit 3(오류)을 구분할 것.** `totalCnt > 0` 인데 결과를 못 뽑으면 파싱 실패이므로
exit 2가 아니라 exit 3으로 낸다 — "결과 0건"으로 오판해 "해당 법령 없음"이라고 결론짓지 않기 위해서다.
(DRF는 결과가 **1건이면 배열이 아니라 객체**로 주고, 결과 노드 키도 target 이름과 달라서
`ordin`·`eflaw`→`law`, `detc`→`Detc` 이다. 스크립트가 흡수하지만 응답을 직접 파싱한다면 반드시 같은 처리를 할 것.)

## 하지 않는 것
- 법령 해석·논증(검토 스킬의 일) · 조문의 임의 요약 인용(원문 그대로 인용) · 미확인 판례번호 생성.
