# 안건 서명부(발의의원 서명부) 작성

의원이 안건을 발의할 때 공동발의 의원의 서명을 받는 공식 서명부를 만든다.
서식 원본은 `assets/template.hwpx`에 내장돼 있다(2쪽·쪽당 15명 정원).

작업 시작 전 `references/template-spec.md`를 한 번 읽을 것 — 문단 인덱스·표 규격·
쪽 확장 규칙·편집 함정이 전부 거기에 있다.

## 산출물

- `{출력폴더}/발의의원 서명부_{안건명 축약}_{YYMMDD}.hwpx`
- 검증용 PDF 렌더는 스크래치패드에만 두고, 사용자에게는 최종 HWPX를 전달한다.

## 1단계 — 입력 수집

| 항목 | 필수 | 비고 |
|---|---|---|
| 안건명 | ○ | 조례안·결의안·건의안의 정식 명칭. 첨부 파일이 있으면 제목에서 추출 |
| 대표발의 의원명 | ○ | 부제 `(○○○ 의원 대표발의)` 자리. 성명만(직함 없이) |
| 공동발의 의원 명단 | △ | `소속`+`성명` 쌍. 없으면 빈 서명부(2쪽)를 만든다 |
| 쪽수 | △ | 미지정 시 인원수로 자동 산정. 여유 칸을 더 원하면 명시 |

첨부된 조례안·안건 파일이 있으면 안건명과 대표발의 의원을 거기서 먼저 추출하고,
못 채운 항목만 한 번에 모아 묻는다.

확인이 필요한 두 가지 — 임의로 단정하지 말고 사용자에게 물을 것:

- **소속 열에 무엇을 넣을지** — 지역구(예: 수원1)인지 정당인지 상임위인지는
  의회·안건마다 관행이 다르다.
- **대표발의 의원을 명단 1번에 넣을지** — 서명부 1번을 대표발의 의원으로 시작하는
  경우도, 공동발의자만 적는 경우도 있다.

발의 정족수(최소 서명 인원)는 의회 회의규칙·조례마다 다르므로 **기억에 의존해
숫자를 단정하지 않는다.** 사용자가 물으면 해당 의회 회의규칙 확인을 권하거나
`law-search` 스킬로 자치법규를 조회한다.

## 2단계 — 빌드

스크래치패드에서 작업한다(최종 경로에서 직접 열면 한/글이 파일을 잡아 다음 빌드가
`PermissionError [WinError 32]`로 실패한다).

1. 설정 JSON을 스크래치패드에 쓴다:

```json
{
  "안건명": "경기도 ○○ 지원 조례 일부개정조례안",
  "대표발의": "홍길동",
  "members": [
    {"소속": "수원1", "성명": "김철수"},
    "성남2|이영희"
  ]
}
```

`members`는 객체(`소속`/`성명`) 또는 `"소속|성명"` 문자열을 섞어 쓸 수 있다.
`pages`를 넣으면 쪽수를 강제한다.

2. 스테이징 HWPX 생성:

```bash
python scripts/build_sheet.py cfg.json stage.hwpx
```

3. 한/글 COM 정품 재저장 + 검증 PDF:

```bash
python scripts/com_save.py stage.hwpx "출력폴더/발의의원 서명부_○○_260807.hwpx" verify.pdf
```

`com_save.py` 없이 스테이징본을 그대로 전달하면 **한/글 보안수준 '높음'에서 변조
문서로 판정돼 열리지 않는다.** 이 단계를 건너뛰지 말 것.

## 3단계 — 검증

`com_save.py`가 출력한 `PageCount`가 예상 쪽수(`ceil(인원수/15)`, 인원 없으면 2)와
같은지 먼저 확인하고, PDF를 이미지로 렌더해 **육안으로** 본다:

```bash
python -c "import pypdfium2 as p; d=p.PdfDocument('verify.pdf'); [d[i].render(scale=1.4).to_pil().save('p%d.png'%(i+1)) for i in range(len(d))]"
```

체크 항목:

- 쪽마다 제목·부제·안건명이 동일하게 들어갔는가
- 연번이 쪽을 넘어 1→15, 16→30, 31→45로 **끊기지 않고 이어지는가**
- 소속·의원명이 밀리거나 겹치지 않는가(글자 겹침은 lsa 잔존 신호)
- **서명 열이 전부 비어 있는가**
- 마지막 쪽의 남는 행이 빈칸으로 정상 출력되는가

텍스트 추출만으로 판정하지 말 것 — 잘리거나 겹친 글자도 PDF 텍스트에는 정상으로
추출된다.

## 동작 원리 (요약)

서식은 `제목·부제·빈줄·안건명·빈줄·표`의 6문단이 한 쪽 블록을 이루고, 2쪽 블록이
연이어 붙은 구조다. 쪽 확장은 표에 행을 더하는 방식이 아니라 **6문단 블록을 통째로
복제**하는 방식이다 — 표는 언제나 16행(헤더 1 + 데이터 15)으로 남아 원본 레이아웃과
쪽 경계가 그대로 보존된다. 남는 행은 지우지 않고 빈칸으로 둔다(서명부는 빈칸이
남는 것이 정상이다).

자세한 내용과 검증된 함정 5가지는 `references/template-spec.md` 참조.
