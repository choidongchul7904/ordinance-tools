# 입법예고 의뢰서 작성 (경기도의회 제정·개정조례)

의원실이 법제과에 입법예고를 의뢰할 때 쓰는 공식 서식을 채워 제출용 HWPX를 만든다.
서식 원본은 법제과 2025-08-12 배포본 2종이 스킬에 내장돼 있다(조직개편에 따른 부서 명칭이 반영된 최신판이므로 구버전 서식을 쓰면 안 된다):

| 조례 유형 | 내장 서식 | 정밀 명세 |
|---|---|---|
| **제정**(새 조례) | `assets/250812-ipbeop-yego-jejeong.hwpx` | `references/template-spec-jejeong.md` |
| **일부개정·전부개정** | `assets/250812-ipbeop-yego-gaejeong.hwpx` | `references/template-spec.md` |

두 서식은 규격·글꼴·안내박스 체계가 같지만 구성이 다르다: 제정판은 3개 블록(공고문 5개 항목·완성 조문·관계법령 발췌)이고, 개정판은 5개 블록(공고문 6개 항목·개정문·신구조문 대비표·현행조례·관계법령 발췌)이다. 조례 유형을 먼저 판별해 서식을 고른다 — 공용 규칙(제명 공백 제거 후 `전부개정`→전부개정, `일부개정` 포함 또는 `개정조례안`·`개정규칙안`으로 끝남→일부개정, 그 밖→제정; ordinance-suite `ordtype.py`와 같은 규칙이 `build_yego.py`에 인라인돼 있다)으로 정하며, 개정이면 개정판, 제정이면 제정판. "일부 개정조례안"처럼 띄어 써도 개정판이다. spec `유형`과 제명이 충돌하면 빌더가 중단한다.

해당 유형의 정밀 명세(문단 인덱스·표 목록·서식 ID·규격 수치)를 채우기 작업 시작 전에 반드시 한 번 읽을 것 — 어느 문단을 바꾸고 어느 표를 지워야 하는지가 전부 거기 있다.

## 두 갈래 — 빌더 우선

**A. 빌더(권장)** — 서식 채우기가 스크립트로 자동화돼 있다. 빨간 안내문 정리·안내 박스 제거·조문 증감·대비표 행 증감·예시 내용 잔존 검사까지 한다.

```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_yego.py" spec.json stage.hwpx --type 제정   # 또는 --type 개정
python "${CLAUDE_SKILL_DIR}/scripts/com_save.py" stage.hwpx "출력폴더/입법예고 의뢰서_○○_260807.hwpx" verify.pdf
```

`spec.json` 스키마는 `ordinance-suite/references/spec-schema.md`와 같다(조례명·유형·대표발의·소관위원회·제안이유·주요내용·본칙/개정문·부칙·관계법령, 개정이면 현행조례명·현행조례·대비표). 조례안 파일에서 자동 추출하려면 `ordinance-suite/scripts/parse_ordinance.py`. 4종 서식을 한꺼번에 만들 때는 `ordinance-suite`가 이 빌더를 호출한다.

개정판의 두문은 **빌더가** `현행조례명`+`유형`으로 만든다 — 일부개정 `「…」 일부를 다음과 같이 개정한다.`,
전부개정 `「…」 전부를 다음과 같이 개정한다.` `개정문`에는 두문 다음 줄부터(지시문·신설 본문)만 넣는다(두문 줄이 섞여 있으면 걷어낸다).
빈 `소관위원회`·`대표발의`·`문의처`는 `○○○위원회`·`○○○`·`○○○과 031)8008-○○○○`로 찍고 경고한다.

회귀 테스트(COM 없음): `python "${CLAUDE_SKILL_DIR}/tests/test_yego.py"` — 고친 뒤 반드시 통과 확인.

값이 빈 블록은 **자리표시자로 덮어쓰고 경고를 낸다** — 서식 정본의 `○○` 자리표시자가 제출본에 남는 것을 막기 위해서다. 경고가 나온 항목은 사용자에게 그대로 알린다.

값이 있지만 **원문을 확인하지 못한** 경우는 이것과 다른 문제다 — 아래 "미검증 콘텐츠 규칙" 참조.

## 미검증(원문 확인 실패) 콘텐츠 규칙 — 절대 준수

law-search·ELIS 조회가 실패했거나 조문 원문을 확인하지 못한 채로 spec.json을 채워야
할 때, **설명 문장을 조문 자리에 그대로 쓰지 않는다.** 예를 들어 아래처럼 쓰면 안 된다:

```
❌ "text": "부칙 제2조는 제3장 및 제22절 및 제72조부터... 재확인할 것."
```

반드시 `[원문 미확인]` 또는 `[확인 필요]` 마커를 텍스트 안에 넣어야 한다. `build_yego.py`가
이 마커를 정규식으로 감지해 **그 항목을 완성본 HWPX에서 자동으로 공란(생략) 처리**하고,
원문 전체를 빌드 로그(stdout)에 `[미검증 — 완성본에서 공란 처리함, 대화창으로만 보고할 것]`
목록으로 출력한다. 마커 없이 설명 문장만 쓰면 가드가 이를 인식하지 못해 **그대로 제출본에
노출된다** — 실제로 이 문제가 한 번 발생해(관계 법령 발췌서에 조회 실패 사유가 통째로 박힘)
이 가드를 만들었다.

```
✅ "text": "[원문 미확인 - 국가법령정보센터 원문 조회 실패, www.law.go.kr에서 재확인 필요]"
```

절차:
1. 원문을 확인하지 못한 항목은 `[원문 미확인]`/`[확인 필요]` 마커로 표시해 spec.json에 넣는다
   (평소처럼 작성하되 마커만 반드시 붙인다 — 상세 사유를 마커 안에 적어도 되고, 어차피
   문서에는 남지 않는다).
2. 빌더 실행 후 stdout에 찍히는 `[미검증 ...]` 목록을 **빠짐없이 대화창으로 사용자에게
   보고한다.** 이것이 유일한 전달 경로다 — 문서 자체에는 절대 다시 적지 않는다.
3. 완성본에서 통째로 빠진 자리(예: 관계법령 한 조문, 신구조문 대비표 한 행)가 있으면
   "제출 전 반드시 채워야 할 항목"으로 명시해 사용자에게 알린다.
4. 법령명 전체가 불확실하거나 한 법령의 조문이 전부 미검증이면 그 법령 블록(□ 표제 포함)
   자체가 통째로 빠진다 — 표제만 남고 본문이 비는 어색한 결과를 막기 위한 설계다.

**B. 직접 편집** — 빌더가 다루지 못하는 변형(문단 구성 자체가 다른 요청 등)일 때만 아래 2단계 절차로 손편집한다.

| 항목 | 비고 |
|---|---|
| 조례명(정식 명칭) | 「」 포함 표기, 제정/일부개정/전부개정 구분 |
| 소관 위원회·대표발의 의원명 | 공고문 첫 문단의 ○○○ 자리 |
| 제정이유 또는 개정이유 (가·나·다…) | 없으면 조례안 취지에서 초안 작성 후 확인 |

| 공고번호·날짜·제출기한 | 미정이면 서식의 빈칸형(제2025-00호, 2025. 00. 00.) 유지 |

## 2단계 — 서식 채우기

작업 순서:

1. 조례 유형에 맞는 내장 서식을 스크래치패드에 `_stage.hwpx`로 복사한다(최종 경로에서 직접 작업하면 한글 프로세스가 파일을 잡아 다음 빌드가 PermissionError로 실패한다).
2. zip 해제 후 `Contents/section0.xml`을 편집한다. 블록별 매핑은 해당 유형의 template-spec 문단 인덱스를 따른다(제정과 개정은 문단 인덱스가 전혀 다르다 — 반드시 자기 유형의 명세를 볼 것).
3. **삭제 대상**(제출본에 남으면 안 되는 작성 안내 요소):
   - 빨간 글씨 안내문 전부 — `(경기천년제목 Medium, 10)` 류 글꼴 표기, `∨` 띄어쓰기 표식, `(조 사이 1줄 띄움)`. charPr id 1(제목체 빨강)·806(바탕체 빨강)을 참조하는 run을 찾아 안내문 텍스트만 제거한다(∨ 자리는 공백 한 칸 유지).
   - 안내 박스 — 「작성 시 주의사항」 박스 2개(내어쓰기 예시 이미지 포함), 개정판은 「전부개정 시」 박스까지 3개. 표를 담은 문단째 제거.
4. **제정이면**: 조례안 본문을 완성 조문(제1조~+부칙)으로 채운다. 조문 수가 예시와 다르면 조문·호·항 문단을 deepcopy로 증식(복제 요소 id 재발급)하고, 조 사이 빈 줄 1개 규칙을 지킨다. 대비표·현행조례 블록은 애초에 없다.
5. **전부개정이면**: 제목을 "…전부개정조례안"으로, 대비표 제목을 "주요조문 대비표"로 바꾸고, 조례안 본문 첫머리에 "「○○ 조례」 전부를 다음과 같이 개정한다." + 새 조례 제목·전문을 넣는다(서식의 「전부개정 시」 박스에 있던 지침 — 박스 자체는 삭제). 빌더는 2026-10-12부터 이 두문을 자동으로 넣는다(이전에는 "일부를"이 하드코딩돼 있었다).
6. 신·구조문 대비표(개정만): 기존 17행을 실제 대비 내용으로 교체. 행이 남으면 삭제, 모자라면 기존 행(tr) deepcopy로 증식. 좌 "현 행"/우 "개 정 안", 변경 없는 조문은 "(생 략)"/"(현행과 같음)", 자구 수정은 줄표(`----`) 관행을 따른다. 셀 안의 바뀐 자구는 `〔U〕…〔/U〕`(U+3014/U+3015) 표식으로 감싸면 빌더가 밑줄 run으로 분할하고 표식 문자는 지운다 — 밑줄 charPr은 셀 기본 charPr(32)을 복제해 underline BOTTOM으로 바꾼 것을 charProperties **맨 끝**에 추가한다(중간 삽입 금지: 한/글 COM 재저장 때 id가 위치 순으로 재부여돼 뒤 id가 밀리고 밑줄 run이 빨간 글자로 변한 사고가 있었다). 빌드 검증에서 표식 잔존 0건을 확인하므로 짝이 안 맞거나 대비표 밖 필드에 쓰면 빌드가 실패한다.
7. 재패키징(mimetype STORED 선두) → 한글 COM으로 Open 후 최종 경로에 SaveAs 'HWPX' 정품 재저장.

### HWPX 편집 시 반드시 지킬 것 (실측 검증된 함정)

- 텍스트를 바꾼 문단과 **높이가 변한 표 행(tr) 전체**의 `<hp:linesegarray>`를 제거할 것. 남기면 PDF에서 글자 겹침, 전체 일괄 제거는 줄바꿈 회귀 — 바꾼 범위만 최소로.
- charPr·paraPr을 추가할 때는 목록 **끝에 이어붙이고 id는 빈틈없이 연속**(id는 위치 인덱스다). 중간 삽입·건너뛴 id는 문서 전체 서식이 조용히 어긋난다.
- paraPr의 margin·lineSpacing은 `<hp:case>`/`<hp:default>` 양쪽에 중첩 — `.iter()`로 두 사본을 모두 고칠 것.
- `<hp:t>` 안에 자식 요소가 있으면 텍스트가 `.text`와 자식 `.tail`에 분산된다 — 치환은 슬롯 전체 순회, 실패 시 문단 재구성 폴백.
- COM `Open()`은 실패해도 False만 반환한다 — 반환값을 검사하지 않으면 빈 문서가 저장된다.
- 경로에 `[ ]`가 든 파일은 PowerShell Copy-Item이 조용히 실패한다 — 파일 조작은 python(shutil)으로.
- 문단·표를 복제했으면 복제 요소의 id를 재발급(기존 max+1 이어붙임)할 것.

## 3단계 — 검증 (통과 전에는 완료라고 하지 않는다)

1. SaveAs 'PDF' → `pypdfium2`로 전 페이지 이미지 렌더 → 육안 검사(텍스트 추출 검사만으로는 잘림·겹침을 못 잡는다).
2. 체크리스트:
   - 편집용지·여백 원본 그대로(A4 세로, 위40·아래32·좌우30·머리말10·꼬리말8mm — 서식에 변경금지 명시)
   - 빨간 안내문 0건 (section0.xml에서 charPr 1·806 참조 run에 텍스트가 남아 있지 않은지 스캔)
   - 미검증 마커(`[원문 미확인]`·`[확인 필요]` 등) 0건 — 빌더가 자동 검사해 남아 있으면
     SystemExit로 빌드를 중단시키지만, 사람도 렌더 PDF에서 한 번 더 확인할 것
   - 안내 박스 제거됨(제정 2개·개정 3개), 의견제출 박스(법제과 연락처)와 참고 라벨 바는 유지됨
   - 제목 경기천년제목 Medium 10pt·본문 경기천년바탕 Regular 10pt 유지, 쪽번호 "- 1 -" 정상
   - (개정) 대비표 좌우 조문이 행마다 정확히 대응, 표가 쪽 경계에서 정상 분할
   - 공고문 항목 번호·순서 원본과 동일(제정 1~5, 개정 1~6), (제정) 조 사이 빈 줄 1개 규칙 준수
3. 불합격 항목은 수정 후 1번부터 재검증.
